## Addressables 热更新方案咨询（同日 15:18）
- 项目调研：塔防游戏，主菜单 + 3 关卡；Unity 2022.3.62f3c1；自有脚本 38 个；无框架/无 Addressables/无热更插件；资源全在 Assets/Resources，Resources.Load 散落 11 个文件（GameDataMgr/UIManager/GameLevelMgr/TowerPoint/MonsterPoint/ChooseHeroPanel/TowerBtn 等），无 .asmdef。
- 方案：P1 本地化改造（装 com.unity.addressables → 建 Static/Remote 组 → 封装 ResourceManager 替换加载点）→ P2 远程热更（Profiles 配 Remote Build/Load Path → Build → HFS 当服务器 → UpdateManager 检查/下载/应用）→ P3 健壮性（进度 UI、重试/版本回退、设计文档+演示 gif）。
- 用户要求：**只给分步实施指南，不代改代码**（再次确认）；服务器用 HFS 模拟。
- 关键坑：Resources+Addressable 双系统会重复打包，须把资源迁出 Resources 目录；ServerData 目录整体拖进 HFS 做根目录；RemoteLoadPath 端口必须与 HFS 一致；Catalog 更新后需重新 LoadAssetAsync 才拿到新资源；下载产物在 persistentDataPath 下。

## xLua 选型澄清（同日 15:25）
- 用户疑问：加 xLua 是否应改用 AB（听说 xLua 与 Addressables 不适配）。
- 澄清：不兼容是误解，xLua loader 签名 byte[] Loader(ref path) 与资源来源完全解耦，Addressables 加载 TextAsset 即可；唯一摩擦点是 loader 同步接口需 WaitForCompletion。
- 方案对比：AB+xLua（老组合教程多但双体系）/ Addressables+xLua（统一链路，推荐）/ Addressables+HybridCLR（热 C# dll，大厂主流，门槛最高）。
- 结论：项目代码全 C# 已写完 → 建议 Addressables 资源热更做扎实，代码热更留扩展点；真要热代码优先 HybridCLR 而非 xLua。P1/P2 方案不受影响。
