## Unity 移动 Resources 子目录的"拒绝访问"坑（同日 10:06）
- 报错：Moving Assets/Resources/Animator to Assets/ResLocal/Animator: 拒绝访问。
- 根因：Unity AnimatorImporter 后台进程持有 .controller 文件句柄，Windows 操作被拒——不是权限问题。
- 解决优先级：① Force Quit（Unity 弹窗中间按钮）→ ② 关 Editor 后用 Windows 资源管理器整目录拖移 → ③ 移动后务必确认 .meta 一起带（隐藏文件），丢了 GUID 断引用。
- 同类预防：移动 Resources 下任何目录（特别是 .controller / .mat / .prefab）都可能触发，先 Force Quit。

## Addressables 批量打组 + 批量设 Address（同日 10:29）
- 用户问题：能否整个文件夹拖进 Groups（嫌逐个拖麻烦）。
- 答：可以拖整个文件夹（Folder Container），Addressables 递归包含；用户已部分配好 StaticGroup（MonsterData/RoleData/SceneData/TowerData/UI 整个拖进）。
- **关键痛点**：Address 默认是文件名（如 `BeginPanel`），代码要的是原 Resources 路径（`UI/BeginPanel`），对不上找不到资源。
- **解决方案**：写 Editor 工具脚本（Assets/Editor/SetAddressTools.cs，~20 行），遍历所有 entry，Path 以 Assets/ResLocal/ 或 Assets/ResRemote/ 开头的，去掉前缀和扩展名作为 Address。菜单 Tools/Addressables/Set Address From Path 一键执行。
- 补充要点：SO 四组目录（RoleData 等）需打 Label，Animator/Animation 不进 Group（prefab 引用自动依赖）。

## SetAddress 持久化问题（同日 10:38）
- 第一次脚本跑后 Address 列从 `MonsterInfo 1.asset` → `MonsterData/MonsterInfo 1.asset`（前缀处理成功，但扩展名未去掉）。
- 根因：Addressables 1.x 的 `SetAddress(string addr)` 单参数版可能未标记 dirty，导致 Address 修改未持久化。
- 修法：改用三参数版 `e.SetAddress(rel, true, true)` + `EditorUtility.SetDirty(settings)` + `AssetDatabase.SaveAssets()` + `AssetDatabase.Refresh()`，并加 Debug.Log 绿色日志方便验证脚本是否真跑了。
- 排查入口：菜单点完看 Console 是否有日志；Groups 窗口选中 entry 看 Inspector 里 Address 实际值。
